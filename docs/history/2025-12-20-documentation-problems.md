## 🔴 CRITICAL: Критические проблемы

### P-001: Несуществующие директории для артефактов

**Тип**: Целостность структуры
**Файлы**: `workflow.md`, `CLAUDE.md`, `.claude/agents/*.md`

**Описание**:
Документация ссылается на директории, которые не существуют в репозитории:

```
docs/prd/           ← НЕ СУЩЕСТВУЕТ
docs/architecture/  ← НЕ СУЩЕСТВУЕТ
docs/plans/         ← НЕ СУЩЕСТВУЕТ
docs/reports/       ← НЕ СУЩЕСТВУЕТ
docs/tasklists/     ← НЕ СУЩЕСТВУЕТ
```

**Фактическая структура**:
```
docs/
├── history/
└── templates/
```

**Затронутые ссылки**:
| Документ | Строка | Ссылка |
|----------|--------|--------|
| `workflow.md` | 80 | `docs/prd/{name}-prd.md` |
| `workflow.md` | 126 | `docs/architecture/{name}-plan.md` |
| `workflow.md` | 184 | `docs/reports/review-report.md` |
| `.claude/agents/analyst.md` | 40 | `docs/prd/{name}-prd.md` |
| `.claude/agents/qa.md` | 41 | `docs/reports/qa-report.md` |

**Влияние на пайплайн**:
- Аналитик не сможет создать PRD в указанной директории
- Архитектор не сможет создать план
- Все агенты, создающие отчёты, не найдут целевые директории

### P-003: Конфликт инструментов между агентами и командами

**Тип**: Конфликт документов
**Файлы**: `.claude/agents/*.md`, `.claude/commands/*.md`

**Описание**:
Агенты и команды объявляют разные наборы инструментов для одних и тех же ролей:

**Аналитик (analyst)**:
```yaml
# .claude/agents/analyst.md
tools: Read, Glob, Grep, Edit, Write

# .claude/commands/idea.md
allowed-tools: Read(*), Glob(*), Grep(*), Edit(**/*.md), Write(**/*.md)
```
Конфликт: Агент имеет полный Edit/Write, команда ограничивает только markdown.

**Реализатор (implementer)**:
```yaml
# .claude/agents/coder.md
tools: Read, Glob, Grep, Edit, Write, Bash

# .claude/commands/generate.md
allowed-tools: Read(*), Glob(*), Grep(*), Edit(**), Write(**), Bash(make :*), Bash(docker :*), Bash(pytest :*)
```
Конфликт: Агент имеет неограниченный Bash, команда ограничивает только make/docker/pytest.

**QA (qa)**:
```yaml
# .claude/agents/qa.md
tools: Read, Glob, Grep, Bash, Edit, Write

# .claude/commands/test.md
allowed-tools: Read(*), Glob(*), Grep(*), Bash(pytest :*), Bash(make :*), Edit(**/*.md), Write(**/*.md)
```
Конфликт: Агент имеет полный Bash, команда ограничивает pytest/make.

**Влияние на пайплайн**:
- Неясно, какой набор инструментов применяется
- Реализатор не сможет выполнить `mkdir`, `cp` для создания структуры
- Возможные ошибки доступа при выполнении команд

### P-004: Отсутствие алгоритма отката при неудаче ворот

**Тип**: Неполнота пайплайна
**Файлы**: `workflow.md`

**Описание**:
Документ описывает сценарий "Откат при неудаче" (строки 396-408), но не определяет:

1. Как именно перезапустить этап после исправления?
2. Сохраняются ли результаты предыдущих этапов?
3. Нужна ли повторная валидация всех ворот?
4. Какой этап перезапускать при частичной неудаче?

**Пример из документации (строки 401-407)**:
```
/validate
→ ❌ QA_PASSED: Coverage 68%
→ Добавить тесты
/test
→ ✓ QA_PASSED: Coverage 76%
/validate
```

**Неотвеченные вопросы**:
- После добавления тестов нужен ли `/review`?
- Если изменился код, остаётся ли `REVIEW_OK` в силе?
- Как отслеживать, какие ворота нужно перепроверить?

**Влияние на пайплайн**:
- Неясный порядок действий при неудаче
- Возможный пропуск необходимых проверок
- Риск деплоя кода с непройденными воротами

### P-021: Нет алгоритма обнаружения входных артефактов для каждого этапа

**Тип**: Неполнота пайплайна
**Файлы**: `.claude/commands/*.md`, `.claude/agents/*.md`

**Описание**:
Каждая команда требует входные артефакты, но **не определяет алгоритм их поиска**:

**Команда /research** (research.md):
```markdown
## Предусловия
| Ворота | Требование |
| `PRD_READY` | PRD документ создан |

❌ НО: Где искать PRD? Какой паттерн?
```

**Команда /generate** (generate.md):
```markdown
## Предусловия
| `PLAN_APPROVED` | План утверждён пользователем |

❌ НО: Как найти план? docs/architecture/*.md или docs/plans/*.md?
```

**Необходимый алгоритм (отсутствует)**:
```python
# Пример того что ДОЛЖНО быть:
def find_prd():
    patterns = [
        "docs/prd/*-prd.md",
        "docs/*-prd.md"
    ]
    for pattern in patterns:
        files = glob(pattern)
        if files:
            return most_recent(files)
    raise ArtifactNotFound("PRD")
```

**Влияние на пайплайн**:
- Агенты не знают где искать входные данные
- Возможен пропуск актуальных артефактов
- Использование устаревших версий файлов

### P-033: Несогласованность количества стадий (7 vs 8)

**Тип**: Конфликт документов
**Файлы**: `workflow.md`, `.ai-framework/docs/reference/ai-navigation-matrix.md`

**Описание**:
Основной проект использует **8 стадий**, а `.ai-framework/` использует **7 стадий**:

**aidd-mvp-generator (8 стадий)**:
```
1. Идея/PRD       → PRD_READY
2. Исследование   → RESEARCH_DONE
3. Архитектура    → PLAN_APPROVED
4. Реализация     → IMPLEMENT_OK
5. Ревью          → REVIEW_OK
6. QA             → QA_PASSED
7. Валидация      → ALL_GATES_PASSED
8. Деплой         → DEPLOYED
```

**.ai-framework (7 стадий с под-стадиями)**:
```
0. Initialization
1. Prompt Validation
2. Requirements Clarification & Intake
3. Architecture Mapping & Planning
4. Generation (4.1, 4.1b, 4.1c, 4.1d, 4.2, 4.2b, 4.3, 4.3b, ...)
5. Quality Verification
6. QA Report & Handoff
```

**Несовместимость**:
- Нет прямого отображения стадий друг на друга
- Разные ворота качества
- Разные критерии перехода

**Влияние на пайплайн**:
- Невозможно использовать оба фреймворка вместе
- Документация противоречит друг другу
- AI получает конфликтующие инструкции

### P-006: Отсутствие алгоритма определения режима CREATE/FEATURE

**Тип**: Неполнота пайплайна
**Файлы**: `workflow.md`, `.claude/agents/analyst.md`, `.claude/commands/idea.md`

**Описание**:
Документация описывает два режима (CREATE и FEATURE), но не определяет:

1. **Кто определяет режим?**
   - Аналитик? Система? Пользователь?

2. **Как определяется режим?**
   - В `researcher.md` (строки 49-53) есть намёк:
     ```
     Если существует src/ или services/:
       → Режим FEATURE
     Иначе:
       → Режим CREATE
     ```
   - Но это в Исследователе, а не в Аналитике (первый этап)

3. **Когда определяется режим?**

### P-031: Нет отдельного агента Deployer

**Тип**: Архитектурное решение
**Файлы**: `.claude/agents/validator.md`, `.claude/commands/deploy.md`

**Описание**:
Команда `/deploy` использует агента **Валидатор**, хотя деплой — отдельная функция:

**Из deploy.md**:
```markdown
## Агент
**Валидатор** (`.claude/agents/validator.md`)
```

**Из validator.md**:
```markdown
> **Назначение**: Финальная проверка всех артефактов и качественных ворот.
> Седьмой и восьмой этапы пайплайна AIDD-MVP.
```

**Проблема**: Валидатор имеет две разные ответственности:
1. Валидация (этап 7) — проверка ворот и артефактов
2. Деплой (этап 8) — сборка и запуск контейнеров

**Нарушение принципа Single Responsibility**:
| Функция | Инструменты | Ответственность |
|---------|-------------|-----------------|
| Валидация | Read, Grep | Проверка документов |
| Деплой | Bash(docker), Bash(curl) | Операции с инфраструктурой |

**Влияние**:
- Смешение ответственностей
- Избыточные инструменты для одного агента
- Путаница при расширении функционала
